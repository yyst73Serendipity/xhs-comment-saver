# 分类拖拽排序设计

## 目标

让管理页左侧分类收藏夹支持调整顺序，交互与 `x-note-saver` 保持一致。用户拖动自定义分类左侧的手柄，即可把分类插入目标分类的上方或下方；新顺序同时保存到本地工作副本，并在已登录时进入 Firebase 同步队列。

## 范围

- “全部”是聚合入口，始终固定在顶部，不属于分类数据。
- “未分类”是系统分类，固定在“全部”之后，不可拖拽、重命名或删除。
- 其余预设分类和用户新建分类均可拖拽排序。
- 保留现有新建、重命名、删除、筛选、AI 总结及评论分类切换逻辑。
- 本次不引入第三方拖拽依赖，不增加移动端触控排序。

## 交互设计

每个可排序分类左侧显示拖拽手柄。手柄在普通状态下保持较低对比度，分类悬停或键盘聚焦时增强；鼠标按下时使用抓取光标。

拖动经过另一个可排序分类时，根据指针位于目标行的上半部或下半部，显示上方或下方插入线。松开鼠标后，源分类移动到相应位置。拖动结束、离开目标或保存失败时，必须清除拖动透明状态和插入线。

点击分类名称仍用于筛选；点击重命名或删除按钮仍执行原操作。拖动必须从手柄开始，避免普通点击误触排序。编辑分类名称期间隐藏拖拽手柄。

## 数据流

1. 页面从后台读取按 `categoryOrder` 投影后的 `categories` 数组。
2. 拖放完成后，在内存中生成新的自定义分类顺序，并立即重渲染侧边栏。
3. 页面向后台发送现有 `reorderCategories` 动作。
4. 后台校验分类集合没有缺失、重复或未知名称，再更新 `settings/main.categoryOrder`。
5. 访客模式直接保存到本机；登录模式追加同步操作，由现有同步引擎上传 Firebase。
6. 后台成功后采用返回的权威顺序重新渲染；失败时显示中文提示并重新读取后台数据，恢复持久化顺序。

## 文件变更

- `manager/manager.js`：分类拖拽状态、手柄、拖放事件、顺序计算和持久化交互。
- `manager/manager.css`：通用拖拽手柄、拖动状态和插入线样式。
- `manager/inspiration-theme.css`：让拖拽反馈适配现有奶油色与胭脂红主题。
- `tests/manager-ui.test.js`：验证固定分类、拖拽入口和排序消息没有因界面修改丢失。
- `tests/account-state.test.js`：验证顺序持久化以及非法顺序拒绝。
- `README.md`：补充分组排序功能和使用方式。

## 错误处理

- 不接受“未分类”作为拖动源或自定义分类目标。
- 拖动源、目标不存在或二者相同时不发送保存请求。
- 后台拒绝缺失、重复或包含未知分类的顺序。
- 持久化失败后恢复后台真实数据，避免界面顺序与云端顺序长期不一致。
- 错误提示使用中文，不影响评论与分类的其他操作。

## 测试与验收

- 测试先行，先观察拖拽界面契约和非法排序测试失败，再实现功能。
- 自定义分类可拖到另一分类上方或下方。
- “全部”和“未分类”始终固定且没有拖拽手柄。
- 排序后刷新管理页，顺序保持不变。
- 已登录账号的排序操作进入待同步队列。
- 保存失败时出现中文提示，界面恢复原顺序。
- 新建、重命名、删除和分类筛选继续正常工作。
- 全量单元测试与构建通过。
