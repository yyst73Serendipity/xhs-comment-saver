# 管理页“灵感剪贴簿”UI 改版设计

## 目标

将现有管理页改造成温暖、清晰且适合长期使用的“灵感剪贴簿”界面。改版只调整管理页的信息结构、视觉样式、响应式布局与交互反馈，不修改收藏、分类、同步、AI 总结或数据分析的业务规则。

设计需要同时满足以下结果：

- 用户进入页面后能立即看到当前 Google 账号、同步状态和最后同步时间。
- 高频操作容易找到，危险操作有清晰区分，顶部不会成为无层级的按钮堆叠。
- 分类侧边栏继续支持新建、重命名和删除，既有数据迁移逻辑保持不变。
- 评论列表仍是主要阅读区域，只让中间列表滚动。
- AI 总结和数据分析在右侧形成两个边界清楚、可独立使用的区域。
- 所有现有 DOM 标识和 JavaScript 事件入口尽量保持稳定，降低视觉改版影响业务逻辑的风险。

## 已确认的设计方向

采用 B 方案“灵感剪贴簿”：奶油纸张背景、胭脂红强调色、深莓色顶部栏和轻微纸张质感。界面应具有收藏手账的亲和感，但不能用过量装饰影响长评论阅读。

视觉上的单一记忆点是“纸张收藏感”：主内容采用柔和点阵纸纹，分类与卡片像整理好的标签和便签。其他区域保持克制，不使用胶带、贴纸、手绘线条等额外装饰。

## 页面结构

页面继续使用固定视口三栏布局：

```text
┌──────────────────────────────────────────────────────────────────────────────┐
│ 品牌 / 收藏数       Google 账号 / 同步状态 / 时间    立即同步 / AI 配置      │
│ 导入 / 导出 / 清缓存 / 清空数据 / 配置帮助                     退出登录      │
├───────────────┬───────────────────────────────────┬──────────────────────────┤
│ 分类侧边栏    │ 搜索 / 排序                       │ AI 总结                  │
│               │                                   │                          │
│ 新建分类      │ 评论卡片与评论组                  ├──────────────────────────┤
│ 重命名/删除   │ 仅此区域滚动                      │ 数据分析                 │
│               │                                   │ 四种视图切换             │
└───────────────┴───────────────────────────────────┴──────────────────────────┘
```

### 顶部栏

顶部栏分两行组织，避免账号信息与所有操作挤在同一行。

第一行使用深莓色背景，包含：

- 产品名称“我的评论灵感簿”和收藏总数。
- 当前 Google 登录邮箱。
- 同步状态、待上传数量或失败状态。
- 最后成功同步时间。
- 主操作“立即同步”。
- “AI 配置”入口。

第二行使用略深的同色背景，包含：

- 导入。
- 导出。
- 清除本机缓存。
- 清空全部数据。
- 配置帮助。
- 退出登录。

“立即同步”使用浅色实体按钮；普通工具使用低对比描边按钮；“清空全部数据”使用危险色文字；“配置帮助”使用带问号图标的强调描边；“退出登录”靠右放置。

同步中禁用会影响同步状态的按钮，并在账号区域显示“正在同步… · N 项待上传”。同步成功显示“已同步 · 今天 HH:mm”；失败显示明确中文原因和可执行的重试提示。

### 分类侧边栏

左侧分类栏固定宽度约 190px，使用浅奶油粉背景。

- 顶部显示“我的分类”和“新建分类”按钮。
- 分类行显示名称与评论数量。
- 当前分类使用胭脂红底色和白色文字。
- 自定义分类在悬停和键盘聚焦时显示重命名、删除按钮。
- 默认分类是否允许编辑继续遵守现有 JavaScript 规则，不通过 CSS 改变权限。
- 新建分类继续使用内联输入框、创建和取消按钮。
- 重命名继续使用现有内联编辑流程。
- 删除继续显示确认弹窗，删除后评论移至“未分类”的现有逻辑不变。

分类按钮必须有可访问名称，不能只依赖图标或悬停状态。键盘焦点下也必须能看到编辑入口。

### 评论主区域

中间区域保持最高视觉权重，采用浅色点阵纸张背景。

- 工具栏包含搜索框、排序按钮和当前结果数量。
- 搜索范围、排序方式及高亮逻辑保持现状。
- 评论卡片使用白色纸张、低对比边框和轻阴影。
- 作者、收藏时间、帖子来源建立清晰的次级信息层级。
- 分类标签、私人笔记状态和笔记操作集中在卡片底部。
- 评论组继续支持展开和折叠，视觉上用左侧细线表达同组关系。
- 卡片中已有的图片、语音、分类切换、笔记编辑和删除交互全部保留。

只允许评论列表滚动。顶部栏、分类栏、搜索工具栏和右侧分析区在普通桌面尺寸下保持可见。

### AI 总结区域

右侧上半区用于当前分类的 AI 总结，约占右栏高度的 44%。

- 标题旁显示当前分类。
- 编辑、AI 生成、导出 Markdown 三个入口继续保留。
- 阅读态使用带胭脂红左边线的纸张卡片。
- 编辑态、加载态、空状态和未选择分类状态沿用现有业务状态，但统一视觉语言。
- 底部显示自动保存结果、更新时间和生成来源。
- 保存失败时保留草稿，并显示明确中文错误，不伪装为已保存。

### 数据分析区域

右侧下半区用于现有成长视图，约占右栏高度的 56%。

- 河流图、网格图、仪表盘、关系图使用带文字的分段切换条。
- 当前视图使用胭脂红实体状态。
- Canvas、图例、提示框和详情弹窗的数据与算法保持不变。
- 空状态说明当前缺少什么数据，以及用户可以怎样产生数据。
- 当前分类与全部数据的作用范围保持现状，界面只负责清晰标示范围。

## 视觉规范

### 色彩

- 深莓顶栏：`#35282D`
- 顶栏第二层：`#2E2227`
- 胭脂红主色：`#E84C5B`
- 深胭脂红：`#BC3546`
- 奶油页面：`#FFF9F5`
- 浅粉侧栏：`#F9ECE5`
- 卡片纸张：`#FFFAF6`
- 主文字：`#392D31`
- 次文字：`#987B76`
- 边框：`#EAD6CE`
- 成功状态：`#2F9A6B`

颜色需要收敛到 CSS 自定义属性，组件不新增零散硬编码颜色。红色只表达选中、主操作、同步警示与图表重点。

### 字体与层级

- 产品名称、区域标题使用系统宋体栈，形成收藏手账气质。
- 正文、按钮和数据使用系统无衬线字体，保证长文本清晰度。
- 不加载远程字体，避免扩展 CSP、离线使用和隐私方面的额外依赖。
- 正文最低 13px；辅助数据最低 11px；可点击按钮最低高度 32px。

### 圆角与阴影

- 大容器：16–20px。
- 评论卡片和分析卡片：12–14px。
- 按钮：7–9px。
- 标签：胶囊圆角。
- 阴影保持低对比，主要依靠边框和背景差异建立层级。

## 弹窗与反馈

既有分类删除、评论删除、清空、导入预览、数据迁移和冲突处理弹窗使用统一结构：标题、说明、内容、取消、主操作。危险确认按钮使用胭脂红或危险红，取消按钮使用中性描边。

Toast 固定在页面右下方分析栏上方，避免遮挡顶部同步状态。成功、提醒和失败使用不同图标与状态色，同时保留可读文字，不能只依赖颜色。

所有异步按钮需要加载、成功、失败和禁用状态。按钮名称与结果提示使用相同动词，例如“立即同步”完成后提示“同步完成”。

## 响应式与可访问性

- `>= 1180px`：完整三栏布局。
- `900px–1179px`：分类栏缩窄，右栏缩窄，顶部工具允许换行。
- `< 900px`：右侧分析区移动到评论区下方，分类栏仍保留；不隐藏任何业务入口。
- 支持 `:focus-visible`，所有可交互元素有清楚焦点环。
- 图标按钮提供 `aria-label` 与 `title`。
- 尊重 `prefers-reduced-motion`，禁用非必要位移和装饰动画。
- 颜色对比度以 WCAG AA 为最低目标。

## 实现边界

主要修改范围：

- `manager/manager.html`：重新组织顶部栏和右侧标题结构，保留既有元素 ID。
- `manager/manager.css`：重建色彩、布局、卡片、弹窗、响应式和可访问性样式。
- `manager/cloud-panel.css`：把账号与同步控件融入新顶部栏。
- `manager/manager.js`、`manager/cloud-panel.js`：只在新结构需要状态类或可访问属性时做局部调整，不改业务数据流。
- `tests/manager-cloud.test.js`：更新结构契约，并覆盖关键入口仍存在。
- 新增专门的管理页 UI 结构测试文件时，仍放在根目录 `tests/`。
- `README.md`：同步更新管理页视觉与布局说明。

不引入 UI 框架、图标包、远程字体或新的运行时依赖。图标优先使用项目内 SVG 或文本图标，不能依赖网络资源。

## 验收标准

- 顶部完整显示账号、同步状态、同步时间和所有确认的全局操作。
- 登录、同步、迁移、冲突、清缓存、退出等现有云端行为保持通过。
- 分类新建、重命名、删除以及删除后的评论归类行为保持通过。
- 导入、导出、清空、搜索、排序、评论组、分类切换和私人笔记功能保持通过。
- AI 总结的编辑、生成、自动保存、导出和错误草稿恢复保持通过。
- 四种数据分析视图均可切换并正确绘制。
- 普通桌面尺寸只滚动评论列表；页面关键控制区保持可见。
- 键盘可访问全部按钮和分类操作，焦点清晰。
- `npm test` 全部通过，构建成功；对实际管理页进行桌面宽度和窄屏视觉检查。

## 风险与控制

- **顶部按钮过多**：通过两行分组与按钮层级解决，不隐藏用户明确要求的操作。
- **视觉改版破坏事件绑定**：保留既有元素 ID，先以 HTML/CSS 改造为主。
- **纸张风格影响阅读**：点阵纹理保持极低对比，评论卡片使用纯色纸张。
- **右栏空间不足**：上下分区各自拥有内部状态，窄屏时改为纵向排列。
- **危险操作误触**：清空和删除继续要求确认弹窗，并使用与普通工具不同的危险样式。
